# 🛤️ Galhoom Path

### Backend tracks — Study · Problem Solving · Interview Prep · Projects · Foundations

Five tracks. Same standards (structure, practice, official sources). Different repo types.

```text
1. 📘 Study           →  learn a subject (Lectures → repo interview set → Final Project)
2. 🧠 Problem Solving →  master DSA patterns with real coding problems
3. 🎤 Interview Prep  →  real interview answer banks / role prep (standalone repos)
4. 🏗️ Projects        →  production / portfolio applications (not Study capstones)
5. 🧭 Foundations     →  stack-agnostic shared backend notes (not a language Study series)
```

> ⚠️ **Important:** *Interview questions inside a Study repo* are lecture-mapped practice for that subject.  
> The **Interview Prep** track below is a **different** thing — dedicated interview repositories, not PHP/OOP lecture checklists.  
> Likewise, **Projects** are real portfolio apps — **not** the `03-Final-Project/` folder inside a Study repo.  
> **Foundations** is curated shared backend knowledge — **not** Lectures → Interview → Final Project, and **not** a PHP/Laravel curriculum.

Maintained by [**@Galhoom22**](https://github.com/Galhoom22).

## 4 · Track 1 — Study (Learning Series)

**Order rule:** finish **1.1**, then **1.2**, then **1.3**… Never skip ahead in the series.

Each Study repo teaches **one subject** with the same method:

```text
Inside every Study repo:
  1. 📚 Lectures
  2. 💼 Interview Questions (subject-mapped)
  3. 🏗️ Final Project
```

✍️ You write every line of code yourself. Guides teach. Official documentation is the source of truth.  
🔗 Repos form a **series with no repeated lessons** — each one starts exactly where the previous one stops.

### How to study

| Step | What you do |
|:---:|:---|
| **1** | Open the **lowest unfinished ID** in the table below (right now: **1.1**) |
| **2** | Open that repo’s root `README.md` and follow **How to Start** |
| **3** | Study **one lecture per session**. Type every example. Run the code. Fill the review card |
| **4** | After all lectures, practice the **subject interview questions** (one per session) |
| **5** | Build the **final project** milestone by milestone |
| **6** | Move to the **next ID** (e.g. **1.1 → 1.2**) when the previous repo is complete |

> ✍️ **Rule:** the tutor (or AI assistant) shows and explains. **You** write, save, and run the code.

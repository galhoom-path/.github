# Galhoom Study Method

Structured, hands-on study paths for software engineering.

Each repository in this organization teaches **one subject** using the same method:

**Lectures → Interview Questions → Final Project**

You write every line of code yourself. Guides teach. Official documentation is the source of truth. Repos form a **series with no repeated lessons** — each one starts exactly where the previous one stops.

---

## How to study here

1. Pick the **first repo you have not finished** in the Learning Series below.
2. Open that repo’s root `README.md` and follow **How to Start**.
3. Study **one lecture per session**. Type every example into the empty `code-N` files in that lecture folder. Run the code. Fill in the `review` study card yourself.
4. After all lectures, practice the **interview questions** (one per session).
5. Build the **final project** milestone by milestone — your proof, not a tutorial copy-paste.
6. Move to the **next repo** in the series when the previous track is complete.

> **Rule:** the tutor (or AI assistant) shows and explains. **You** write, save, and run the code.

- Self-taught developers filling gaps with official sources

---

## Principles (short)

| Principle | Meaning |
|:---|:---|
| Official sources only | PHP Manual, official docs, release notes — not random blogs |
| Latest stable version | Repos stay current (living curriculum) |
| Max 2 new concepts per lecture | Depth over dumping |
| Analogy before code | Understand the idea, then write it |
| You write all the code | Show ≠ substitute for practice |
| No framework until the path says so | Foundations first |
| Help yourself, help others | Public repos others can follow the same way |
